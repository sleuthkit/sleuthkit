# Read-only FTL100 NOR image layer

Branch `feature/ftl100` starts from `develop-4.1x` at cac76b4. It adds an
image backend, not a new filesystem: physical NOR -> translated logical image
-> ordinary partition and filesystem readers, including existing FAT12 support.
No temporary reconstructed image is needed; reads use the physical source.

```
img_stat dump.bin
fsstat dump.bin
fls -r -p dump.bin
icat dump.bin INODE > file.bin
img_cat -i ftl100 dump.bin > recovered.img
img_cat -i raw dump.bin > unchanged-physical-copy.bin
```

`-i ftl100` forces translation. Automatic detection checks for an FTL100
header signature in the first MiB after other container formats have been
excluded. Explicit selection searches the whole dump and handles prefixes,
headers crossing read boundaries and split raw image segments. No ECC, OOB
or stuff-byte processing is performed. Logical sector size is 512 bytes.

The recovery policy is adapted from `Gerd1986/qnxprobe`, branch `ftl`, commit
dfa12f2231ef5900ade8fb61aefd6166357ebdcc, file `ftl100.py` (MIT).
Header offsets and BAM type interpretation were cross-checked against Linux
`drivers/mtd/ftl.c` and the MTD FTL definitions. That driver does not establish
the BMW-specific absolute-EUN recovery convention used by the user's parser.

* Absolute logical EUNs are normalized against FirstPhysicalEUN using the same
  rule as the tested BMW preprocessor; relative EUN numbering is also accepted.
  Numbering schemes whose ranges overlap are not independently disambiguated.
* For a duplicate EUN, the higher erase count is retained; ties retain the first.
  This is the reference recovery heuristic, not proof of transaction recency.
* `BLOCK_DATA` BAM entries supply logical-to-physical sector mappings.
  Duplicate logical sectors use the last entry in first-seen EUN order,
  matching the Python preprocessor. Duplicate counts are reported by img_stat.
* Transfer units and BAM entries representing free/deleted/replacement blocks
  are excluded. Missing mappings are zero-filled recovery holes, not asserted
  original zero content. img_stat reports the mapped and missing counts.
* Invalid shifts, sizes, BAM bounds, metadata-overlapping data entries,
  out-of-range logical sectors and truncated matching erase units fail closed.
  A recognized malformed FTL image is not silently treated as raw.

All offsets, partition layouts, file runs and filesystem Unallocated results
above this backend refer to the reconstructed LOGICAL address space.
`blkls` therefore extracts free logical FAT blocks, not deleted physical NOR
sectors, superseded erase units or transfer-unit contents. Use `-i raw` to
preserve/analyze the complete original physical dump. Translation is read-only.

Native and Java image-type IDs include FTL100 (0x0200); Windows JNI/CLI and
Linux builds include it. `tests/ftl100_regression.py` compares entire logical
images against the pinned Python recovery and checks FAT12 extraction,
fragmentation, prefixes, duplicate-EUN selection/ties, missing and deleted BAM
entries, split images, buffered boundary reads, malformed structures and raw
bypass. The fixture is independently generated and contains no vehicle data.
The user's original physical BMW dump has not been retested in this branch.
