# Native read-only QNX4 support

Branch `feature/qnx4` starts at `develop-4.1x`, commit
`497fa5100f5f5e96639b14fbe00ece9b385922b2`. F2FS changes are on a separate branch.

The driver supports automatic detection and explicit `-f qnx4`, filesystem
partition offsets, 512-byte blocks, 64-byte directory inode entries, 16-byte
inline names, 48-byte linked names, hardlinks, symlinks, Unix mode/UID/GID/link
count, mtime/atime/ctime, and chained `IamXblk` extents. `di_ftime` is not mapped
to a creation timestamp because its exact semantics are not established.

Allocation is read from `.bitmap`, including extent-fragmented bitmap files.
Bits are low-bit first; set means allocated. `blkls` exposes free blocks for
carving. Filesystem-relative disk pointers are one-based and are translated to
zero-based TSK block addresses. Readable partial images can open; missing or
out-of-range referenced extents fail explicitly. Cyclic/invalid xblk chains and
invalid linked inode slots are rejected instead of silently truncating data.

Inode walking indexes active reachable directory entries and valid superblock
system inodes. It does not scan arbitrary file bytes for inode-shaped records.
Deleted inode/dentry reconstruction and orphan-inode discovery are not implemented.

Examples:

```
fsstat image.img
fls -r -p image.img
icat image.img INODE > extracted.bin
istat image.img INODE
ils -a image.img
blkls image.img > unallocated.bin
fls -f qnx4 -o 2048 disk.img
```

Reference: `abrignoni/qnxprobe` at commit
`de0e352b466e2e165cf5dd38652b11515ccf58f4`, `Qnx4Walker` and `identify_qnx4` in
`qnxprobe.py`. Its MIT license is in `tsk/fs/qnx4_LICENSE.txt`. Disk field widths
were checked against Linux's QNX4 headers. Allocation bit semantics were also
checked against the historical Linux QNX4 bitmap implementation.

Validation is synthetic; no confirmed real-world QNX4 image is available in this
test corpus. The independent fixture generator extends qnxprobe's synthetic
selftest layout with nested/multi-block/short-final-block directories, exact
16/48-byte names, hardlinks, symlinks, metadata, zero-length files, 3 extents,
63 extents over 2 xblk blocks, a fragmented bitmap and deleted-content marker.
31 file payloads are compared both to known generated bytes and to qnxprobe.
Additional tests cover allocation positions/counts, inode enumeration,
partition offsets, MBR type 0x4d, boot-sector/MBR distinction, partial images and 9 malformed structures.
Release packages run these checks on Linux and on packaged Windows executables.
